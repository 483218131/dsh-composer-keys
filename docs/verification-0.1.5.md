# dsh-composer-keys · DSH 0.1.5-rc.1 浏览器断言清单

适用版本：`dsh 0.1.5-rc.1`（输入框为 Lexical `<div contenteditable data-composer-input>`）
被测对象：本仓库 `lib/client.js`（`feat/arrow-cascade-cursor`，Step 1 适配后）
执行方式：人工在浏览器中逐条操作并记录；**全程不需要发送任何消息**

> 本清单只覆盖「按键行为」这一类可观察事实。设计依据见 `HANDOFF.md` §3/§4/§10。

---

## 0. 前置条件

| # | 操作 | 期望 | 失败即 |
|---|---|---|---|
| 0.1 | 在 DSH Web 里按 **Ctrl+Shift+R** 硬刷新 | 页面正常重新加载 | 插件未重载，后续全部无效 |
| 0.2 | 打开 DevTools Console，执行：`document.querySelectorAll('[data-slot-error]').length` | 返回 `0` | 值为 `≥1` 说明 composer 槽渲染崩了（典型原因：插件重复 `provide` 官方已声明的 hooks/props），**立即停止后续测试并上报** |
| 0.3 | 打开任意一个**已有 ≥2 条历史用户消息**的会话（建议用闲置旧会话） | 输入框可正常打字、Enter 可发送 | — |
| 0.4 | 准备「长草稿」：在输入框里粘贴或输入 **≥3 行**文本，例如 `第一行`／`第二行`／`第三行`（每行按 Shift+Enter 换行，不要提交） | 输入框内显示 3 行 | 单行草稿测不出「中途不劫持」，见 §7 坑 3 |

每条断言独立执行。若某条导致草稿被弄乱，先 **Ctrl+A → Delete** 清空再继续。

## A. ↑ 翻历史（草稿为空）

| # | 操作 | 期望 |
|---|---|---|
| A1 | 输入框为空、光标在框内 → 按 **↑** | 草稿被填为**最后一条**用户消息的全文 |
| A2 | 紧接着再按 **↑** | 替换为**倒数第二条**用户消息 |
| A3 | 连续按 ↑ 直到最早一条，**再按一次 ↑** | 停在最早一条，不循环、不清空、不报错 |
| A4 | 在 A1/A2 之后观察光标 | 光标落在**文本末尾**（官方 `setDraft` 契约：整体替换 + 光标到末尾），可立即继续输入 |

**取样要求**：至少有一条历史消息**超过一屏可见高度**，确认填入的是**全文**而不是被截断的预览。
（`chat.navigation.items()` 的 `prompt` 是**有界预览**，方案里刻意没用它——若发现长消息被截断，说明取错了数据源。）

## B. ↓ 回退

| # | 操作 | 期望 |
|---|---|---|
| B1 | 接着 A2 按 **↓** | 回到更晚的一条历史 |
| B2 | 一直按 ↓ 越过最新一条 | 恢复**你开始按 ↑ 之前原本的草稿**（原本为空则恢复为空） |
| B3 | **不先按 ↑**，直接按 ↓ | 无任何反应（不报错、不清空、不填历史） |

## C. 中途不劫持（级联语义的核心，HANDOFF §5 ② 的实测点）

| # | 操作 | 期望 |
|---|---|---|
| C1 | 用 0.4 的长草稿，鼠标点在**中间行的中间位置** → 按 **↑** | 草稿**一个字符都不变**，只有光标向上移动一行 |
| C2 | 连按 ↑，直到光标停在**第一行行首**，**再按一次** ↑ | 这一次才翻历史（草稿被替换为最后一条历史） |
| C3 | 重来：光标放在**第一行但不是行首**（例如第一个字之后）→ 按 **↑** | 草稿不变，光标移到行首或上一位置；**不得翻历史** |
| C4 | 对称测 ↓：光标放在**最后一行末尾** → 按 ↓ → 期望翻回；光标在**最后一行中间** → 按 ↓ → 期望草稿不变、只移动光标 |

**C 组是本轮唯一不能靠静态阅读定论的断言。** 它验的是：原生/官方光标移动是否发生在我们判定端点**之前**。

- C1/C3/C4 全部通过 → 说明「按键前的端点真值」取到了，级联语义成立。
- 若 C1 或 C3 直接跳出历史消息 → **上报，这正是要抓的失败**。当前实现用「capture 阶段记录端点 + bubble 阶段决策」来防这一点，失败说明该设计不成立。

## D. IME 守卫

| # | 操作 | 期望 |
|---|---|---|
| D1 | 切到中文输入法，敲拼音让候选框**停在未上屏**状态 → 按 **↑** | 候选框正常上下选择；**草稿不被历史替换** |
| D2 | 用 ↑/↓ 在候选词里选词后上屏 | 上屏的是选中的候选词，不是历史消息 |
| D3 | 上屏后**立刻**（10ms 内）再按 ↑ | 不误触发历史（官方有 `compositionend` 后 10ms 守卫窗口；本插件用 `isComposing`/`keyCode 229`，此项**允许失败**，失败按「已知差距」记录即可） |

## E. Ctrl+C 清空

| # | 操作 | 期望 |
|---|---|---|
| E1 | 草稿非空、**没有选中任何文本** → 按 **Ctrl+C** | 草稿被清空 |

## 失败模式对照表（上报时请对号入座）

| 现象 | 最可能的根因 |
|---|---|
| ↑/↓/Ctrl+C **全部无反应**，但能正常打字 | 监听器没挂上，或输入元素没被识别（`[data-composer-input]` 不匹配） |
| 草稿填的是**被截断**的短预览 | 历史取到了 `chat.navigation.items().prompt` 而非 `legacy.nodes` |
| C1/C3 直接翻历史 | 端点判定晚于原生光标移动，capture/bubble 双阶段设计失效 |
| Ctrl+C 在**有选中**时也清空 | 选区判定失效（读到了 `el.selectionStart` 这类 contenteditable 上不存在的属性） |
| 0.2/G1 出现 `[data-slot-error]` | `uiSession.provide` 撞名（本次实现刻意**没有**任何 `provide`，若出现说明有别的改动） |
| 翻历史后光标不在末尾 | `setDraft` 契约变化 |

## 附：为什么不需要发送消息

本清单全部断言都建立在「输入框里的草稿文本」这一可观察事实上，`setDraft` 是唯一被触发的写入路径。历史消息来自会话**已有**内容，无需新建会话，也无需提交任何 prompt。
